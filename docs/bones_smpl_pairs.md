# BONES G1 / SONIC SMPL pairing

This prepares data for jointly trained G1, SMPL and teleoperation encoders with a shared FSQ decoder. It does not implement the new encoders or start training.

## Inputs and identity

Use the existing frozen bones_full_v1_s0 catalogs and the official nvidia/GEAR-SONIC SMPL archive extracted into bones_seed/smpl_extracted/smpl_filtered. Exact metadata filename, CSV stem and PKL stem must agree. Preserve _M mirror suffixes. Duplicate identities are excluded rather than guessed. Actor/source splits remain unchanged.

Reference: https://github.com/NVlabs/GR00T-WholeBodyControl/blob/main/gear_sonic/utils/motion_lib/motion_lib_base.py
Joint training overview: https://nvlabs.github.io/GR00T-WholeBodyControl/user_guide/training.html

## Run

Requires NumPy and joblib. Only deserialize trusted official PKLs.

```bash
python tools/build_bones_smpl_pairs.py \
  --root /path/to/data/bones_seed \
  --out /path/to/data/bones_seed/paired/bones_smpl_v2 \
  --workers 8
```

The output directory must be new to avoid overwriting a frozen manifest.

Outputs: train.jsonl, val.jsonl, test.jsonl (full reserved groups), val_fixed100.jsonl, test_fixed100.jsonl (intersection with the original fixed evaluation sets), unmatched.jsonl, report.json. Records retain source metadata, motion ID, relative paths, source/mirror groups, revisions and SMPL SHA256. Missing evaluation items are listed, never silently replaced.

## Time and acceptance contract

G1 is 120 Hz; inspected official SMPL has 50 Hz pose_aa (T,72), transl (T,3), smpl_joints (T,24,3), plus original_pose_aa/original_fps. Validate every matched file for expected shapes, finite values and endpoint agreement for both 120-to-original30 and original30-to-final50 resampling stages (record each offset; up to one discarded frame per stage). Future adapters must sample both modalities at t=k/50 on their common time interval; do not stretch either motion to force equal length.

A matched record means identity/schema/duration compatibility, NOT independently verified spatial or semantic correspondence. Before training adapters, validate SMPL axes, units, joint ordering, local versus global joints, initial heading and three-point device transforms. Do not treat stored smpl_joints as world positions without checking their convention. No VR recordings are present or generated by this tool.

## Training direction

The user-selected next stage is joint multi-encoder training, not mandatory sequential frozen-decoder distillation. Existing FSQ64/proprio93 Motion policy remains a baseline. SMPL and teleop branches, modality sampling and alignment losses still need implementation and closed-loop validation; sharing token dimension alone does not establish interoperability.
